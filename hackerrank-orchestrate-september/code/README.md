# Buy or Wait?

For each row in `dataset/requests.csv`, this decides whether the user can safely
pay in full, pay part now, take one of the seller's installment options, wait, or
not proceed — and writes `output.csv`. It rebuilds each user's cash position from
their events, detects which commitments recur, projects the balance 90 days
forward, and reports the largest payment that never takes the balance below the
minimum they want to keep. **The arithmetic is entirely deterministic code.** A
language model is used for exactly two things: transcribing a document when an
event's amount is blank, and turning a free-text message into a typed change to
an event that already exists. Every number in `output.csv` is computed from the
resulting ledger, never emitted by a model.

## Run it

```bash
UV_PROJECT_ENVIRONMENT=../.venv uv run python main.py
```

Writes `../output.csv` (the graded file, at the run root), `evaluation/run_manifest.json`,
and regenerates `evaluation/usage_report.md` from that manifest. Exits `0` only
if the output gate passes on the file it just wrote. `dataset/` is never written to.

```bash
PYTHONDONTWRITEBYTECODE=1 UV_PROJECT_ENVIRONMENT=../.venv uv run python -m pytest
```

797 tests, **no network and no cost** — every suite runs offline, including the
ones that read `dataset/`. Add `-m "not dataset"` to skip those anyway; the rest
run in about a second. The pipeline's perception layer is exercised by
`evaluation/harness.py --perception`, which is billed and is not part of the
suite.

## Setup from a clean checkout

Python 3.11.x and [uv](https://docs.astral.sh/uv/). The tree expects `code/` and
`dataset/` side by side:

```text
<run root>/
├── dataset/        provided, read-only
├── code/           this directory — the contents of code.zip
├── .env            SARVAM_API_KEY=…   (outside code/, so the zip cannot capture it)
└── output.csv      generated by the run
```

```bash
UV_PROJECT_ENVIRONMENT=../.venv uv sync --python 3.11
UV_PROJECT_ENVIRONMENT=../.venv uv run python scripts/check_env.py
```

`uv sync` byte-compiles the package, which leaves `__pycache__` directories
inside `code/`. They never reach the archive — `scripts/build_zip.py` excludes
them and re-opens the archive to prove it — but `tests/test_submission_hygiene.py`
fails on them by design, because they must not be in what gets zipped. Clear them
before building or before running the suite:

```bash
find . -name __pycache__ -type d -prune -exec rm -rf {} +
```

The virtualenv goes **outside** `code/` because `code/` is zipped and graded.
`check_env.py` verifies the credential is present and well-shaped, that
`models.yaml` names the variable rather than holding a value, and that no
key-shaped string exists anywhere under `code/`. It prints the key's length and
nothing else about it.

If the dataset or the credential live elsewhere:

```bash
BOW_DATASET_DIR=/path/to/dataset BOW_ENV_PATH=/path/to/.env \
  UV_PROJECT_ENVIRONMENT=../.venv uv run python main.py
```

Nothing else is configurable by environment.

## Runtime and cost

| | wall time | model calls | cost |
|---|---|---|---|
| full run, 250 requests | 24 min | 408 | **₹118.16** (~USD 1.34), ₹0.47/request |
| `--no-perception`, 250 requests | ~2 s | 0 | ₹0 |

`--no-perception` runs every decision rule with no vision, no messages and no
network. Use it to check the solver. Vision reads are cached under `code/.cache/`
by image id, so a re-run does not pay for them again; the cache is excluded from
the archive. `evaluation/usage_report.md` is regenerated by every full run from
that run's manifest, so it always describes the `output.csv` currently on disk.

## Which module produces which output column

| output column | computed by | rendered by |
|---|---|---|
| `request_id` | copied from the request row — `bow/pipeline.py` | — |
| `amount_safe_to_pay` | `bow/engine/capacity.py` — closed form, proven equivalent to a search over 500 generated cases | `bow/format/amounts.py` |
| `affordability_status` | `bow/engine/policy.py` — raises rather than emit a row that breaks a post-condition | — |
| `recommended_payment_method` | `bow/engine/policy.py`, over candidates from `bow/engine/plans.py` ranked by `bow/engine/ranker.py` | — |
| `payment_plan` | `bow/engine/plans.py` — installments follow a supplied option exactly | `bow/format/columns.py` |
| `earliest_date_for_full_payment` | `bow/engine/capacity.py` | `bow/format/amounts.py` |
| `spending_changes_needed` | `bow/engine/changes.py` — subset search, hard cap of three | `bow/format/columns.py` |
| `decision_explanation` | `bow/explain/template.py` — rendered from the frozen decision, so it cannot introduce a number the ledger does not contain | — |

## Where each financial rule is enforced

AGENTS.md §6.3, in order:

| rule | enforced in |
|---|---|
| Detect recurrence only when history supports it | `bow/data/recurrence.py` — cadence claimed only at ≥2 occurrences (Q18) and only inside a staleness multiple (Q19) |
| Forecast essential variable spending conservatively | `bow/engine/forecast.py` — trailing-window rate behind a minimum-occurrences guard (Q26). **Partly: see LIMITATIONS L4** |
| Reserve pending debits | `bow/data/normalize.py` — `cash_treatment`, `PENDING_DEBIT_RESERVED` (Q1) |
| Do not count pending credits … until they settle | `bow/data/normalize.py` — `cash_treatment`, `PENDING_CREDIT` dropped (Q9) |
| Count confirmed salary on its settlement date | `bow/data/normalize.py` — settlement-date basis, which also keys the FX lookup (Q16) |
| Do not invent unsupported facts | `bow/perception/untrusted.py` — a delta naming no existing event row is dropped (Q7, Q13) |
| Balance never below `minimum_balance_to_keep` | `bow/engine/plans.py` `is_schedule_safe`, over the whole horizon, re-checked in `bow/engine/policy.py` |
| Respect protected categories and preferences | `bow/engine/changes.py` — `ChangePermission`, required with no default; `bow/engine/plans.py` for accepted methods |
| Rank: deadline, no changes, least cost, earlier, fewer payments | `bow/engine/ranker.py` — one tuple, `sort_key`, plus problem_statement.md's sixth key (lowest option id) |
| Conflict resolution order | `bow/data/normalize.py` for cancellation/settlement, `bow/perception/untrusted.py` for amendment, the configured default for the financially safer reading |

## Module layering

```text
                    contracts        pydantic models; imports nothing internal
                        ^
      +-----------+-----+-----+-------------+
   engine      format      explain      validate
    (pure)     (pure)         |             ^
                              v             |
                          providers  <------+---- perception ---- data
                                                                     ^
                                       settings · paths · usage      |
```

Enforced by `tests/test_layering.py`:

- **`contracts/` imports nothing internal.** Everything can depend on it, so it can depend on nothing.
- **`engine/` and `format/` import `contracts/` only** — never perception, data, providers or settings.
- **`engine/` and `format/` do no I/O, no clock reads, no randomness, no network.** Same input, same output, always; this is what makes the solver testable with zero API calls.
- **`explain/` may reach `contracts/`, `providers/` and `format/`** — it renders prose containing numbers, so it needs the formatters.
- **`providers/` is the only package permitted a network call.** It owns the rate limiter, job poller, retries and the usage meter.
- **One vendor.** `tests/test_no_sdk_leak.py` fails on a second one, or on a vendor SDK imported outside `providers/`.

## Accuracy, measured on the 25 published examples

The sample set is the only labelled data available, so these are the only
accuracy figures that exist. They are a 25-row sample, not an estimate of the
evaluation score. Reproduce with `python evaluation/harness.py`.

| metric | deterministic path, 20 scorable rows |
|---|---|
| `affordability_status` | **14/20** |
| `recommended_payment_method` | **17/20** |
| `payment_plan`, exact string | **16/20** |
| `earliest_date_for_full_payment`, exact | **12/20** |
| implied trough, median relative error (**primary**) | **10.0%** over 14 invertible rows |
| `amount_safe_to_pay`, median relative error (secondary) | **44.8%** over the same 14 rows |
| clamp-bound rows, reported separately | 6 |
| schema validity | 100% |
| vision gold set | 16/16 |

Two error figures are reported because they measure the same error against
different denominators. The trough is what the forecast predicts; the safe
amount is the trough minus a constant, then clamped, so its relative error is
always the larger number. Neither is quoted without its name.

With perception enabled all 25 rows are scorable: status 19/25, method 21/25,
plan 20/25, earliest date 16/25.

**The largest known weakness** is that variable spending is under-forecast, which
is the unsafe direction — it overstates what is safe to pay. `LIMITATIONS.md` L4
has the detail, and L1 through L11 have the rest, including three defects found
and fixed during review and one that is still open.
